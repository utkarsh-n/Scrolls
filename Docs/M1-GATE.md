## Still broken or missing after M1 (by severity, as the gate saw it)

- 1. Not checked in a real browser. Every UI module is served and imports, and the UI's request builders work against the real server, but layout, canvas painting, the import button, the narrow sheets and console errors are unverified. The lead should run the 1440×900 and 375×812 check against the real server. A fully bootstrapped data dir (demo, Cipher, 3 imports, saved view m1-gate-carry-the-zero-8fef, annotation 26) is at /private/tmp/scrolls-m1-journey-2RJhMY.
- 2. Proper-noun guard over-flags title words in Cipher culture titles (WP3 heuristic; SPEC §4.5 title rule read literally). 17 of 31 'zero' culture-work titles are excluded as names, e.g. 'Zero Dark Thirty', 'Ground Zero', 'Zero Hour', 'Below Zero' (any capitalised neighbour that appears in some of the 268k maker names). Culture-title rates are therefore undercounted. The exclusion is visible (names_excluded) and overridable per match, but this needs a lead decision on the heuristic.
- 3. Docs/M1-GATE.md and Docs/ANALYSIS-AND-LIMITS.md are not on disk: this subagent harness refuses to create new .md files (the same refusal WP4 reported). The gate record is this output. The ANALYSIS-AND-LIMITS text is WP4's verbatim text in its needs_from_others; a session allowed to write .md files must create both. Docs/API.md (an existing file) was updated.
- 4. Performance budgets missed on the full Cipher DB (bench). Tiles cold p95 618 ms (budget ≤ 300): the first request per tier in each of the 3 read workers pays a 0.45–0.63 s full-tier denominator scan, then 1–3 ms. The first timeline query per worker takes 1.8 s; later expressions 1–9 ms. Search p95 179 ms (budget ≤ 120), mostly theme suggestions (LIKE scan over 285k theme tags; label_tri covers only 4,213 of 15,287 theme values, so it cannot replace the scan). Within budget: warm tiles 1.2 ms, marks 2.3 ms, health during a CPU-bound job 20.1 ms.
- 5. Bootstrap targets missed (WP2/WP0): phase A 39.1 s (≤ 30 s); A + A2 95 s (≤ 60 s). WP2's attribution to SAVEPOINT exec is wrong: measured at 0.5 µs per SAVEPOINT/RELEASE pair, about 50 ms over 94k documents. The cost is DocumentWriter's inserts, and that part is not fixed. Full bootstrap 235.7 s, within ≤ 10 min.
- 6. WP4 P2 stubs show at first launch: demo-load enqueues 2 'cluster' jobs that fail NOT_IMPLEMENTED and appear as failed jobs in the jobs tray. GET /api/clusters and /api/constellation answer 404, and the demo's deferred label rename stays pending.
- 7. Interactive writes are protected only between bulk transactions. A single long write transaction (more than 5 s) in a job could still produce E_BUSY. None was observed in the journey after the fix. The job queue's own main-thread flushes do not take part in the handoff.
- 8. As-saved is partial: the timeline (pinned materialize runs plus import cutoff), lineage and notebook honour it, but inspector passage cards (annotation counts, relationship counts), Compare and arcs (P2) show current data. A document reverted after a view was saved is excluded even 'as saved'.
- 9. Decisions made at the gate, for the lead to confirm: es translations stay at 2 (bilingual school editions remain mixed-language under the 70% rule; not relabelled). The vantage default stays strict:true in viewstate, and WP6's 'paused views open in context' behaviour is kept. 'contested' was added to the pragmatic_function enum (contract 1.1.0).
- 10. Additive contract items still open (P2 or optional): tiles carry no first/last observed day per strand, so caps are drawn at bin precision (WP6). /api/kwic has no denominator.tokens, so the inspector's contemporary-uses line prints n only (WP7). date_card has no lo_year/hi_year, so WP7 parses the label. No shapes for the SSE data/bootstrap/adapter events. The jobs tray does not show an import job's summary (WP1 optional).
- 11. Minor: search returns empty_note null when a tracked expression's current count is 0 but its last run still counts reverted documents (until it is re-materialized). DocumentWriter keeps every MinHash signature in memory for a batch (about 0.5 KB per document; risk for multi-million-row streamed imports).
