# Shared offline text generation

Scrolls now uses the portfolio's `OfflineIntelligence` API and `OfflineIntelligenceMLX` implementation for text generation. Qwen3.5 2B, 4-bit is the initial default; Qwen3.5 4B, 4-bit is optional in Diagnostics → Qwen on this iPhone → Text model. The selection is saved under the shared preference key `offlineIntelligence.modelChoice` in this app's own settings. A selected 4B model does not silently fall back to 2B.

The specialist Qwen3-Embedding-0.6B, 8-bit backend remains responsible for context vectors. Its pooling, Matryoshka normalization, batch plan, gate thresholds and representation keys are unchanged. `ModelManager` closes work admission across actor suspensions, cancels and drains active work before unloading, and holds `MLXExternalModelLease` while embedding weights are resident. It unloads and drains the shared text runtime before acquiring that lease, then releases the embedding model and GPU work before loading text weights. Two model backends cannot own MLX residency simultaneously.

The memory guard also cancels `QwenHost`'s outer demo/self-test task before manager unload for memory warnings, critical memory pressure, backgrounding and critical thermal events. This covers file verification and vector grouping between model operations, preventing the pipeline from starting another model load after an unload event.

The specialist embedder uses `MLXForegroundExecution` before residency and before every GPU batch, including a recheck after the interaction wait. Cleanup drains CPU work but submits a GPU barrier only while foreground execution is allowed; the pinned MLX barrier itself commits a Metal command buffer. Tokenizer-only counts and shared generation now use the same public local tokenizer bridge and bundled chat template.

Generation goes through the shared runtime only. The original domain prompt is retained, and its JSON schema is added to the system instructions. Shared text inference uses greedy sampling, seed 42, a 1,024-token rendered prompt limit, a 4,096-token context budget, the domain output cap and the domain deadline. The shared backend uses 128-token prefill chunks; Scrolls waits for active manipulation before admission instead of inserting a scheduling callback inside the shared prefill loop.

The shared decoder does not apply the former XGrammar token mask. Results explicitly record `unconstrained; strict domain validation follows`. Scrolls still checks complete generation, strict label fields/types/lengths/citation IDs through `LabelValidator`, then grounding through `Verifier`, before showing a generated label. A token limit, timeout, cancellation, malformed output or rejected citation does not become a displayed reading. Future task adapters must retain their own validators too.

Every new generation result includes the exact model ID and revision, effective shared request, completion metrics and model name. Current badges use that recorded name. Historical reports without the new optional fields still decode and retain their original model badges; old results are not attributed to Qwen3.5.

Models are local files under `Models/qwen-2b`, `Models/qwen-4b` and `Models/Qwen3-Embedding-0.6B-8bit` in the app bundle, with Documents/Models imports taking precedence. Scrolls checks each model's compiled file sizes and SHA-256 values before loading; the shared runtime additionally checks repository/revision/quantization metadata. The verified model catalogs are pinned to the same Qwen3.5 revisions as the physical-phone benchmark. No model downloader or cloud fallback was added.

`Native/Tools/build.sh device` routes to the shared `OfflineIntelligenceKit/Tools/build_hosts.py --app Scrolls` pipeline, which stages a sibling shared package and local models outside Documents and records source parity/build evidence. Existing pure-test commands remain available. Full legacy mirror commands can use `Tools/bundle-shared-models.py` to verify and clone the same three local models. Bundled weights are build artifacts, not committed source. The active simulator hold remains in force.

The central helper's Scrolls branch clones `~/Developer/scrolls-models/Qwen3-Embedding-0.6B-8bit` into the staged app's `Scrolls/Resources/Models/Qwen3-Embedding-0.6B-8bit`; the `Models` folder is a resource entry in `project.yml`. The integration coordinator runs the staged `Tools/bundle-shared-models.py` against `Scrolls/Resources/Models` before the device build to check the compiled embedding hashes as well as the generation hashes. Runtime `ModelStore` uses that bundled folder when a Documents model is absent and still checks its catalog before residency.

Verification for this integration: **32 ScrollsQwen pure Mac tests passed**, including five shared adapter cases for schema instructions, domain budget preservation, distinct non-complete stop reasons, citation rejection after a complete shared response, pinned model choices, JSON report round trips and historical report compatibility. These tests use synthetic shared metrics; they do not establish real inference speed, embedding/generation switching, or physical UI behavior in Scrolls. The generic-device build and phone delivery are separate checks recorded by the integration coordinator.
